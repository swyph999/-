## IEKF：迭代扩展卡尔曼滤波	在同一次观测更新中，多次重新线性化和修正  
   
我们举一个机器人用“IMU＋测距传感器”定位的例子。
假设机器人只能沿地面向前移动，前方有一个反光标。反光标比传感器高 3米，我们想知道机器人与它的水平距离 \(x\)。
传感器测到的是斜距，因此：

```math
\text{斜距} = \sqrt{x^2 + 3^2}
```

现在有两条信息：
- IMU预测： 水平距离约为 1米，但误差比较大。
- 测距传感器： 斜距为 5米，测量比较准确。
按勾股定理，水平距离应该在 4米附近。

问题是：滤波器不会直接套勾股定理解完整系统，而是从当前估计出发，用线性近似来修正。 这个例子只保留一个变量，方便看清过程。  
采用一组示例噪声参数后，更新过程如下：  

| 阶段 | 估计的水平距离 $x$ | 对应的斜距 | 与测得的5米相比 |
| :---: | :---: | :---: | :---: |
| IMU预测 | 1.00米 | 3.16米 | 偏小 |
| 第一次修正 | 6.67米 | 7.31米 | 修正过头了 |
| 第二次修正 | 4.12米 | 5.10米 | 已经接近 |
| 第三次修正 | 3.99米 | 4.99米 | 基本吻合 |
| 第四次修正 | 3.99米 | 4.99米 | 收敛 |

示例采用：预测位置标准差2米，测距标准差0.1米。  

EKF通常在第一次修正后结束这次观测更新；IEKF会在修正后的位置重新计算线性近似，再继续修正。 这里初值离正确位置较远，第一次近似不够准确，所以迭代带来了明显改善。  

注意，整个过程中机器人没有继续移动，传感器也没有测四次。我们始终使用同一个“5米”的观测，并保留同一个IMU预测及其不确定性，只是反复求解这次融合更新。最终没有恰好等于4米，是因为滤波器仍然考虑了IMU预测。  

换成激光SLAM，就是把这个简单的“斜距误差”，换成激光点与地图表面的对齐误差；把一个水平距离 \(x\)，换成位置、姿态等多个状态。  

## **问：每一次修正的原理是什么呢，，比如说imu预测水平距离为1米，斜距3.16.对比5确实是偏小了，但是第一次修正的6.67是·怎么估计确定的呢？**  

**6.67米是在IMU预测值的基础上，加上“测量残差 × 卡尔曼增益”算出来的。** 其中，卡尔曼增益同时考虑了两件事：**水平距离变化会让斜距变化多少，以及IMU预测和测距各有多可信。**

我们沿用刚才的数据，一步步算。

## ① 先算斜距差了多少

水平距离是 $x$，斜距模型为：

```math
h(x)=\sqrt{x^2+9}
```

IMU预测 $x=1$，因此预测的斜距为：

```math
h(1)=\sqrt{10}\approx3.162
```

实际测到5米，二者的差称为**残差**：

```math
r=5-3.162=1.838\text{米}
```

但这个 **1.838米是斜距的差，不能直接当作水平距离的修正量**。需要先知道两者如何变化。

## ② 用导数，把斜距变化和水平距离变化联系起来

对测量模型求导：

```math
H=h'(x)=\frac{x}{\sqrt{x^2+9}}
```

在当前估计 $x=1$ 处：

```math
H=\frac{1}{\sqrt{10}}\approx0.316
```

意思是：**在 $x=1$ 附近，水平距离每增加一小段，斜距大约增加这段长度的0.316倍。**

所以，局部可以近似成：

```math
\text{斜距变化}\approx0.316\times\text{水平距离变化}
```

如果完全相信测距，并直接使用这个近似，为了补上1.838米的斜距差，就需要：

```math
\Delta x\approx\frac{1.838}{0.316}\approx5.811
```

得到水平距离：

```math
x_{\text{新}}\approx1+5.811=6.811\text{米}
```

这已经很接近前面说的6.67米了。**两者的差别来自对预测和测量不确定性的考虑。**

## ③ 加入不确定性，就得到6.67米

前面的例子设置了：

- IMU预测的标准差为2米，因此预测方差 $P=2^2=4$；
- 测距标准差为0.1米，因此测量噪声方差 $R=0.1^2=0.01$。

一维情况下，卡尔曼增益为：

```math
K=\frac{PH}{H^2P+R}
```

代入数值：

```math
K=\frac{4\times0.3162278}{0.3162278^2\times4+0.01}
\approx3.085
```

因此：

```math
\boxed{
x_{\text{新}}
=1+K\,r
=1+3.085\times1.838
\approx6.67\text{米}
}
```

这里的 $K$ 是把**斜距残差换算成水平距离修正量**的系数，所以可以大于1。

## ④ 为什么会修正过头，下一次又怎么改？

因为刚才的 **0.316只是 $x=1$ 附近的斜率**，而我们一下子把 $x$ 改到了6.67，已经离原来的位置很远了。此时继续使用原来的直线近似，就不够准确。

IEKF会在 $x=6.67$ 处重新计算：

```math
h(6.67)\approx7.313,
\qquad
H=\frac{6.67}{7.313}\approx0.912
```

新的斜率表明：**在这个位置附近，同样的水平距离变化，会引起更大的斜距变化。** 用新的近似再求解，估计就会回到约4.12米。

不过，后续迭代必须始终保留原来的IMU预测 $x_{\text{先验}}=1$ 和方差 $P=4$。完整更新公式是：

```math
K_k=\frac{PH_k}{H_k^2P+R}
```

```math
\boxed{
x_{k+1}
=x_{\text{先验}}
+K_k\left[
5-h(x_k)+H_k(x_k-x_{\text{先验}})
\right]
}
```

第一次 $x_k=x_{\text{先验}}=1$，括号里的最后一项为0，就变成上面算过的 $1+Kr$。

第二次代入新斜率和新预测斜距：

```math
x_2
=1+1.0932\left[
5-7.3133+0.9120(6.6696-1)
\right]
\approx4.124
```

因此，每次修正都在做同一件事：**在当前估计处重新求导，用更合适的局部线性模型，重新计算如何兼顾IMU预测和这次测距。**
